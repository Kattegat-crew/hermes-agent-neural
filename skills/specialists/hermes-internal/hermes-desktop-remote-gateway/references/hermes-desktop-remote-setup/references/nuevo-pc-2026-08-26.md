# Caso real: PC nuevo conectado al gateway remoto (26/08/2026)

## Contexto
Jonathan pidió configurar Hermes Desktop en un PC nuevo con modo "Remote
gateway". Dudó preguntando "¿qué URL pongo?" y luego "¿será que no tengo la
clave SSH guardada en este equipo?".

## Síntomas y causa raíz
1. Primero puso como URL su **propia IP Tailscale** (100.112.161.72) → el
   Desktop se quedaba "pensando". La URL debe ser la del SERVIDOR
   (`http://100.86.8.81:9112`).
2. El PC no aparecía en `tailscale status` del host — estaba logueado en la red
   equivocada. El usuario dijo "ya está en red, no había entrado a la red"
   (mkt-golde-lucky). Una vez logueado con la cuenta `digitalexpresions1@`,
   el tailnet mostró:
   ```
   100.112.161.72  mkt-golde-lucky  digitalexpresions1@  windows  -
   ```
3. Confusión sobre SSH: la auth del Desktop es HTTP basic, no SSH. Se aclaró y
   se procedió con usuario `desktop` + password.

## Valores finales usados
- URL: `http://100.86.8.81:9112` (vps-dev-neural, `hermes-serve` systemd)
- Usuario: `desktop`
- Password: en `/root/.hermes-serve.env` del host (HERMES_DASHBOARD_BASIC_AUTH_PASSWORD)
- Resultado: conexión exitosa tras "Test remote → Save for next restart → Save
  and reconnect".

## Lecciones derivadas (ya en SKILL.md)
- URL remota = IP del servidor, nunca la del cliente.
- El PC debe estar en el MISMO tailnet que el VPS (misma cuenta Tailscale).
- SSH keys irrelevantes para Desktop ↔ serve.
- Probar salud del serve desde el namespace del host (302/401), no desde el
  contenedor (timeout HTTP 000 esperado contra IP Tailscale).
